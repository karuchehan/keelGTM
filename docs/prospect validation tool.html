The Solution

What the Prospect Validation Tool does

An internal xGrowth web tool. Upload prospect CSV + client brief → AI scrapes each LinkedIn profile → validates against target personas → writes verdict + sales note back into the CSV.

Input

Prospect CSV + client brief (.md) + value prop PDF. Uploaded through the web interface.

Process

Scrapes LinkedIn via Apify. 20 concurrent validation threads. Claude Sonnet judges each profile against the directive.

Output

Verdict (Persona / EXCLUDE) + assessed persona + 12-word strategist note per row, back into CSV.

New Workflow

The integrated process — step by step

1

Strategist writes the list building brief

Tight, contextual directive with personas, keywords, exclusion signals, and seniority rules. This is the upstream input that determines tool output quality.

2

Insights Team bulk-pulls from Sales Navigator via Evaboot

No per-profile evaluation during pull. Get everyone matching broad keyword and seniority filters. Volume is fine — the tool handles it.

3

Run through Prospect Validation Tool

Upload CSV + brief. Tool scrapes LinkedIn, validates each profile, returns verdict + persona + strategist note per row. ~20 mins for 500 prospects.

4

Insights Team review — build final list + reserve sheet

Move validated includes to final list. Green-highlight marginal excludes into a separate reserve Google Sheet. Hard excludes are done. ~1 hour total.

5

Strategist review

Top-to-bottom scan of final list. 5–15 mins. Any gaps → Insights Team checks reserve sheet first before going back to Sales Navigator.

6

Enrichment via Clay → Delivery Manager → Client

Existing Steps 6–8 process unchanged. Email, phone, quality check, handoff. Nothing downstream changes.

Architecture Detail

The reserve sheet system

How flagged prospects are stored, accessed, and actioned — without creating overhead for the Insights Team.

Final List Sheet

All tool-validated ✓ includes. Clean, ready for Strategist review. Verdict + persona + note populated per row.

Reserve Sheet

All ⚠ marginal excludes highlighted green by Insights Team during first pass. Hard excludes are not carried over.

How the reserve sheet gets used

1

Strategist flags gaps in final list ("need 2 more IT Ops contacts for ANZ")

2

Insights Team opens reserve sheet, reviews only green-highlighted prospects — seconds, not hours

3

If reserve has no suitable options → only then return to Sales Navigator for new prospects

Each Insights Team member maintains their own reserve sheet per campaign. Owned, structured, instantly accessible.

Known Exception

Private profiles & thin LinkedIn presence

The tool scrapes LinkedIn. Private profiles and low-presence accounts can't be fully scraped — a known, bounded exception, not a system failure. Senior leaders are often the least active on LinkedIn.

What happens

Private profiles → Evaboot cannot download. Thin profiles → tool flags with ⚠ or returns scrape error. Disproportionately affects senior security and IT leaders.

How it's handled

Insights Team manually reviews these during the initial build pass. Validate against brief manually. Same old procedure, applied only to the exception cases — not the full list.

The rule

If a profile cannot be scraped or returns insufficient data → Insights Team handles manually, flagged in the sheet with a note. This preserves coverage for high-value contacts who are deliberately low-profile — often the most important ones to capture.

Private profiles are a small minority. This does not materially affect the overall timeline.

Critical Dependency

Brief quality determines tool quality

The tool's judgment is only as good as the directive it operates against. A weak brief produces confident-sounding wrong answers at scale. This is the single most important upstream input.

What a good brief must include

✓

Precise persona descriptions per bucket

✓

Explicit example titles (primary + secondary)

✓

Domain keywords for functional background check

✓

Hard exclusion signals (role types, career patterns)

✓

Seniority floor (Head / Director / VP minimum)

✓

Industry context (APRA, regulated, ASX, etc.)

✓

Federated structure notes (group vs divisional)

✓

Wiggle room guidance for borderline profiles

This becomes a formal Strategist deliverable. The brief is not optional context — it is the system's operating instructions. Brief quality = output quality.

Brief quality ownership & standardisation

Tool confidence threshold — when to override

The tool is accurate but not perfect on borderline cases. What is the agreed protocol when the Insights Team or Strategist disagrees with a verdict? How are corrections fed back to improve the directive?

⚠

Reserve sheet ownership at scale

Each Insights Team member managing reserve sheets per campaign — how is this structured, named, and filed so it remains accessible and doesn't become disorganised across 20 campaigns?

⚠

Rollout sequence

Do we pilot on one campaign before full rollout? Who manages the transition for in-progress builds already mid-process under the old workflow?
